# DipTrace — заполнение пропусков позиционных обозначений

Автономная HTML-утилита для схем DipTrace в формате XML (`.dchxml`). Она убирает пропуски в нумерации позиционных обозначений (RefDes): `C1, C2, C4, C7 → C1, C2, C3, C4`.

**Открыть онлайн:** https://wadi-li.github.io/diptrace-refdes-repair/

Работает полностью локально: один файл `index.html`, без установки, сервера и интернета. Схема не покидает компьютер, сетевые запросы запрещены политикой CSP прямо в странице.

## Быстрый старт

1. Сохраните резервную копию схемы и экспортируйте её из DipTrace в `.dchxml`.
2. Откройте `index.html` (или ссылку выше) и перетащите файл в окно.
3. Исправленный файл `имя_RefDes_fixed.dchxml` скачается автоматически, если есть что исправлять.
4. Проверьте лог замен на экране, при необходимости поменяйте группы или начальный номер и скачайте файл заново кнопкой внизу.
5. Откройте результат в DipTrace и проверьте схему, надписи и синхронизацию с PCB.

Исходный файл не перезаписывается.

## Возможности

### Автоматическое скачивание
- Включено по умолчанию: исправленный DCHXML скачивается сразу после загрузки и успешной проверки.
- По желанию вместе с ним скачивается протокол CSV (второй файл идёт с задержкой; браузер может один раз спросить разрешение на несколько загрузок).
- Если пропусков нет, файл не скачивается, а в журнал пишется причина.
- Настройки запоминаются в браузере.

### Лог замен на экране
| Вкладка | Что показывает |
|---|---|
| Сводка по группам | секции, уникальные номера, диапазон «было», число пропусков, переименования, диапазон «станет» |
| Переименования | пары «было → станет» с числом секций, поиск и фильтр по группе |
| Подробный лог замен | каждая изменённая секция: № секции, строка в файле, было/станет, `ComponentPart`, Value, компонент библиотеки, смещение в байтах; режимы «изменённые / все / без изменений» |
| Не перенумеровываются | обозначения, которые утилита сознательно не трогает, и причина |
| Журнал | кодировка, BOM, переводы строк, предупреждения, результаты проверок, скачивания |

Выгрузки: протокол CSV, подробный лог CSV, журнал TXT. CSV — разделитель `;`, UTF-8 с BOM, экранирование кавычек и разделителей.

### Удобство для больших схем
- Список групп в боковой панели с фильтром, сортировкой (по имени, числу секций, пропускам) и кнопками «все, кроме портов», «только с пропусками», «снять», «инвертировать» (действуют на отфильтрованные группы).
- Таблицы с закреплённой шапкой, поиском и постраничным показом по 500 строк.
- Пересчёт с задержкой 250 мс при вводе, линейная сборка результата: 6000 секций и 4800 замен проверяются примерно за 0,1–0,4 с.
- Нижняя панель с кнопками скачивания всегда на экране.
- Светлая тема по умолчанию, переключатель тёмной темы.

## Кодировки

Изменяются только цифры номера, причём прямо в исходных байтах файла. Всё остальное — BOM, XML-декларация, переводы строк (CRLF/LF), библиотека, поля BOM — остаётся побайтно прежним.

| Вход | Как определяется |
|---|---|
| UTF-8 с BOM и без BOM | BOM или декларация / по умолчанию |
| UTF-16 LE/BE с BOM | BOM |
| UTF-16 LE/BE без BOM | сигнатура `<?` в первых байтах |
| Windows-1251, KOI8-R, CP866, ISO-8859-5 | `encoding="..."` в XML-декларации или ручной выбор |

После замены результат декодируется заново и сравнивается с ожидаемым текстом; при расхождении файл не формируется.

### Исправленные ошибки версии 1.x
- Игнорировался `encoding` из XML-декларации: файл в Windows-1251 вызывал непонятную ошибку декодирования. Теперь кодировка читается из декларации, а при неверном UTF-8 указывается байт, смещение и строка.
- UTF-16 без BOM не распознавался.
- Конфликт BOM и декларации не отмечался — теперь это предупреждение (приоритет у BOM по правилам XML).
- `R01` и `R1` считались одним компонентом и могли слиться в одно обозначение. Номера с ведущими нулями теперь не перенумеровываются.
- Буква `Ё` не входила в допустимые префиксы. Теперь допускаются любые буквы Unicode и `_`.
- Кириллическая «С» и латинская «C» выглядят одинаково, но для DipTrace это разные группы. Утилита помечает алфавит и предупреждает о внешне одинаковых префиксах.
- Обозначения, записанные XML-сущностями (`&#51;`) или в CDATA, могли быть заменены некорректно. Сущности теперь не меняются, CDATA поддерживается.
- Пробелы вокруг RefDes удалялись при замене — теперь сохраняются.
- Текстовый разбор сверяется с DOM: при любом расхождении числа секций или значений RefDes файл не изменяется.
- Повторный выбор того же файла не срабатывал; сообщение об ошибке не сбрасывалось.

## Алгоритм

- Проверяются корректность XML и корень `<Source Type="DipTrace-Schematic">`.
- Обрабатываются `RefDes` у `Part` внутри `Schematic/Components`; библиотека не меняется.
- Формат обозначения: буквенный префикс + номер без ведущих нулей.
- Номера каждой выбранной группы уплотняются по возрастанию прежнего номера (не по положению на листе), начиная с заданного номера.
- Одинаковые префикс и номер — секции одного компонента, они переименовываются вместе.
- Порты цепей (`PartType="Net Port"` в библиотеке или префикс `NetPort`) по умолчанию не выбраны.
- После замены: повторный разбор XML, сверка каждой секции с ожидаемым обозначением, проверка коллизий в группах и контроль кодировки.

## Ограничения

- Иерархические (`#1.1-R1`) и нестандартные обозначения показываются, но не перенумеровываются.
- Текстовые надписи на листе, внешние ссылки и PCB не обновляются.
- Случайно одинаковые RefDes у разных деталей считаются секциями одного компонента.
- UTF-32 и кодировки вне списка не поддерживаются.
- Проверено в Chromium на синтетических файлах из папки `examples/` (UTF-8, UTF-8 с BOM, UTF-16 LE/BE, Windows-1251, 6000 секций). Открытие результата в самом DipTrace в рамках этой версии не проверялось — обязательно проверьте результат на своей схеме.

## Файлы

- `index.html` — утилита.
- `examples/` — тестовые схемы в разных кодировках, включая большую (6000 секций).
